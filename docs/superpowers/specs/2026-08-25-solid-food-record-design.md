# 辅食记录功能设计

## 目标

在现有宝宝记录工具中增加独立的辅食记录能力。用户应能单手完成录入，并能与家人在同一房间内共享当天及历史记录。辅食数据不得影响奶量、喂奶次数或“距上次喂奶”计算。

## 范围

本次包含：

- 新建、查询和删除辅食记录。
- 在房间详情中返回当天辅食记录。
- 在首页大按钮组中增加辅食入口。
- 在今日统计、今日记录和历史记录中展示辅食。
- 支持食物名称、食用量、单位、时间、记录人和备注。
- 对辅食录入流程进行桌面端和移动端浏览器验证。

本次不包含：

- 编辑已有辅食记录。
- 过敏反应、接受程度或营养成分记录。
- 常用食物模板、快捷复用或辅食摄入分析。
- 对现有记录类型进行通用事件模型重构。

## 数据模型

新增 `solid_food_records` 表：

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | TEXT | 主键 | UUID |
| `room_id` | TEXT | 非空、外键 | 关联 `rooms.id`，房间删除时级联删除 |
| `recorder_name` | TEXT | 可空 | 沿用首页记录人 |
| `food_name` | TEXT | 非空 | 去除首尾空格后必须有内容 |
| `amount_value` | REAL | 可空 | 食用量，填写时必须大于 0 |
| `amount_unit` | TEXT | 可空 | `g`、`ml`、`spoon`、`bowl` 或 `NULL` |
| `note` | TEXT | 可空 | 用户备注 |
| `started_at` | TEXT | 非空 | ISO 8601 时间 |
| `created_at` | TEXT | 非空 | 服务端创建时间 |

新增 `(room_id, started_at)` 索引。食用量未填写时，`amount_value` 和 `amount_unit` 均保存为 `NULL`；用户选择“无单位”时，食用量正常保存且 `amount_unit` 为 `NULL`。

## 服务端结构

SQLite 仓储新增 `SolidFoodRow`、`getSolidFoods`、`insertSolidFood`，并把 `solid_food_records` 加入受控的删除表名联合类型。所有 SQL 继续集中在 `src/storage/database/sqlite.ts`。

新增接口：

- `POST /api/rooms/[id]/solid-foods`：创建辅食记录。
- `GET /api/rooms/[id]/solid-foods?days=N`：按现有中国时区记录周期查询。
- `DELETE /api/solid-foods/[solidFoodId]`：删除指定记录。

房间详情接口增加 `solid_foods` 字段，返回当前记录周期内最多 50 条辅食记录。创建接口要求 `food_name` 非空；`amount_value` 如存在则必须是有限且大于 0 的数字；无食用量时忽略单位。接口返回结构沿用 `{ success, data, error }`。

辅食使用独立表和查询，不加入 `getFeeds`、`getLastFeed` 或奶量汇总，因此不会改变现有喂奶业务语义。

## 客户端结构

首页 `RoomData` 增加 `solid_foods`，并维护历史辅食列表。房间轮询、打开历史记录及切换历史天数时一并获取辅食数据。

为控制首页文件规模，新增两个聚焦组件：

- `SolidFoodForm`：底部录入面板，负责字段输入、客户端校验、提交状态和错误展示。
- `SolidFoodRecordRow`：统一渲染今日及历史列表中的辅食内容。

页面继续负责打开/关闭面板、调用接口、刷新房间数据和删除记录。组件沿用项目内联主题色和 Tailwind 布局规范，不引入新的状态库或表单依赖。

## 录入交互

首页循环横向大按钮组从四种操作扩展为五种，增加带餐具线条图标的“辅食”按钮，同时调整循环宽度计算，保持现有居中缩放和无限滚动行为。

点击“辅食”后打开移动端底部面板：

1. 食物名称，必填，打开后自动聚焦。
2. 食用量，数字输入，可为空，允许小数。
3. 单位，下拉选择克、毫升、勺、碗、无单位；默认克。
4. 日期与时间，沿用今天/昨天加时间输入。
5. 备注，可选。
6. 大号确认按钮。

记录人沿用首页当前值并保存到 `recorder_name`。提交期间按钮显示“保存中”且不可重复触发。成功后关闭面板并刷新房间数据；失败时保留输入内容并在面板内显示简短错误，允许重试。

## 展示方式

今日统计在有辅食记录时显示“辅食 N 次”。辅食记录与喂奶、大便、吃药、清醒记录按 `started_at` 混排。

列表主内容为食物名称，后接可用的“数值 + 中文单位”，再显示记录人和时间。备注存在时作为次要文本展示。辅食使用餐具线条图标和柔和绿色作为识别色，整体仍遵循暖奶白背景、低对比边框和单手大触控区规范。

今日记录与历史记录均沿用左滑删除。删除成功后刷新房间数据和当前历史列表；删除失败时重新拉取服务端状态，避免本地与共享房间状态不一致。

## 校验与错误处理

- 客户端在食物名称为空或食用量不是正数时阻止提交并显示字段错误。
- 服务端重复执行相同校验，不能依赖客户端保证数据合法。
- 时间沿用现有今天/昨天转换逻辑并以 ISO 8601 传输。
- 网络或服务端提交失败时不关闭面板、不清空内容。
- 获取历史数据失败时保持现有页面可用，不写入不完整记录。

## 验收标准

- 用户可以创建只包含食物名称和时间的最简辅食记录。
- 用户可以记录小数食用量以及克、毫升、勺、碗等单位。
- 空食物名称和非正数食用量在客户端及服务端均被拒绝。
- 新记录会出现在今日统计、今日记录和对应日期的历史记录中。
- 家人通过相同房间可以在轮询或刷新后看到辅食记录。
- 用户可以从今日记录或历史记录左滑删除辅食记录。
- 创建或删除辅食记录不会改变奶量、喂奶次数、上次喂奶记录及喂奶间隔。
- `pnpm run validate` 和 `pnpm run build` 通过。
- 浏览器验证覆盖桌面和移动视口，页面无框架错误层、相关控制台错误、文字溢出或控件遮挡。
- 浏览器完成一次创建辅食记录、查看今日/历史展示、删除记录的真实交互闭环。

## 风险与约束

首页按钮循环逻辑当前依赖固定操作数量，新增辅食按钮时必须同步更新每组宽度及三组重复渲染，避免滚动跳转错位。当前项目没有自动化测试脚本，因此本次以类型检查、Lint、生产构建、API 验证和浏览器交互验证覆盖风险，不引入新的测试框架。
