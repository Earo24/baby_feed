# 辅食记录键盘布局设计

## 目标

修复手机端打开辅食记录后呼出键盘的布局问题：食物名称输入框和当前焦点保持可见，表单字段可以在键盘上方滚动，确认按钮始终位于面板底部且不与表单内容重叠。

## 现状与原因

辅食记录使用 Vaul `Drawer`，内容面板设置了 `max-h-[90dvh]`，表单主体和确认区采用纵向 flex。组件还会自动聚焦食物名称输入框。iOS 键盘覆盖布局视口时，Vaul 需要知道面板应如何处理输入框和高度；当前 `Drawer` 没有显式启用固定面板策略，较高的表单会让确认区与可视区域竞争，出现输入框被确认按钮遮挡的情况。

吃药记录是页面内的简单底部弹窗，确认按钮和字段关系更直接。本次沿用其“底部确认区独立存在”的交互意图，但保留辅食面板已有的字段滚动和 Drawer 无障碍能力。

## 方案

- 在辅食 `Drawer` 根节点启用 Vaul 的 `fixed` 与 `repositionInputs` 键盘处理，让键盘出现时面板调整高度而不是把确认区推到表单内容上。
- 面板使用接近全屏的动态高度上限，并保持 `overflow-hidden`；表单字段区继续使用 `min-h-0 flex-1 overflow-y-auto`，确认区使用 `shrink-0` 和安全区底部内边距。
- 给字段滚动区增加底部滚动内边距，确保最后一个备注字段在确认区上方有足够的可视缓冲；确认按钮不进入滚动区。
- 不新增自定义 `visualViewport` 状态或全局 CSS，优先使用 Vaul 已有的输入框重定位实现，避免与 Drawer 内部键盘逻辑竞争。

## 验收

- 桌面视口：辅食面板字段、备注和确认按钮均可见，确认按钮位于面板底部。
- 移动视口：自动聚焦食物名称时输入框完整可见；切换到备注或数量输入时，字段可滚入键盘上方，确认按钮不遮挡字段。
- 关闭、提交、校验错误和现有吃药弹窗行为不变。
- `pnpm test` 中新增布局契约测试通过；`pnpm run validate` 和 `pnpm run build` 通过。
